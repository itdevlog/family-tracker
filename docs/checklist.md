# Полевой чек-лист Family Tracker

Проверка на двух реальных телефонах: телефон родителя и телефон ребёнка. Сервер уже развёрнут по `deploy/README.md`, APK собран и установлен по разделу «Установка APK» в том же README.

Перед началом:

- на обоих телефонах включены интернет, геолокация и точное определение местоположения;
- известны адрес API (`https://api.example.com`) и доступ к серверу для проверки логов/БД;
- на телефоне ребёнка есть запас заряда и мобильный трафик на 1–2 часа проверки;
- отмеченные пункты — обязательные; если пункт не проходит, приложите модель телефона, версию Android/прошивки и время.

Обозначения: **OK** — ожидаемое поведение подтверждено, **FAIL** — отклонение с описанием.

## 1. Установка и первый запуск

1. Соберите APK из корня репозитория: `cd app && ./gradlew assembleRelease`.
2. Установите на телефон родителя (команда из корня репозитория): `adb install -r app/app/build/outputs/apk/release/app-release.apk`.
3. Передайте тот же файл на телефон ребёнка (кабель, мессенджер, облако) и установите, разрешив «Неизвестные источники» для файлового менеджера/мессенджера.
4. На обоих телефонах откройте Family Tracker.
5. На телефоне родителя выберите «Я родитель», на телефоне ребёнка — «Я ребёнок».

**Ожидаемо:** приложение запускается без вылета, показывает выбор роли; после выбора открывается экран регистрации (родитель) или привязки (ребёнок). Повторный запуск не спрашивает роль заново.

## 2. Привязка семьи

### Родитель

1. Введите адрес сервера строго в виде `https://api.example.com` (без пути) и имя.
2. Нажмите «Создать семью».
3. Дождитесь экрана «Код для привязки ребёнка» с QR-кодом и шестью цифрами.

**Ожидаемо:** семья создаётся один раз; на экране виден QR и срок действия кода. Повторная регистрация на том же сервере даёт понятное сообщение, что семья уже создана (без потери уже сохранённого токена).

### Ребёнок — QR

1. Нажмите «Сканировать QR», разрешите камеру.
2. Наведите камеру на QR с телефона родителя.
3. Проверьте сервер, код и имя, нажмите «Привязать».

**Ожидаемо:** привязка проходит, открывается детский экран; код одноразовый. Повторное использование того же кода даёт «Код уже использован».

### Ребёнок — ручной ввод

1. Нажмите «Ввести код вручную».
2. Введите адрес сервера, шесть цифр с экрана родителя и имя ребёнка.
3. Нажмите «Привязать».

**Ожидаемо:** результат тот же, что при сканировании; без камеры/Play Services привязка работает.

### Повторная привязка и сброс семьи

1. На ребёнке: «Настройки → Приложения → Family Tracker → Память → Очистить данные», затем снова выберите роль ребёнка.
2. На родителе: «Показать QR для привязки ребёнка» → создайте новый код → привяжите ребёнка заново.
3. Для полного сброса выполните раздел «Сброс семьи» в `deploy/README.md`, затем очистите данные приложения на обоих телефонах и пройдите привязку заново.

**Ожидаемо:** новый код привязывает ребёнка; после сброса семьи старые токены отклоняются, приложения показывают «Нет доступа к серверу» / ошибку авторизации, пока данные не очищены и семья не создана заново.

## 3. Wizard ребёнка и запуск трекинга

1. На детском экране откройте «Проверить настройки фона».
2. Пройдите шаги: геолокация «Всегда», уведомления, «Без ограничений батареи», автозапуск производителя.
3. Вернитесь в приложение и нажмите «Разрешить и включить отслеживание».
4. Разрешите геолокацию и уведомления, если системные окна появились.
5. Сверните приложение и откройте шторку уведомлений.

**Ожидаемо:** все шаги отмечены «выполнено» (для автозапуска — после ручного подтверждения); в шторке видно постоянное уведомление «Отслеживание включено»; в приложении нет ошибки о нехватке разрешений. Остановка трекинга запрашивает подтверждение.

## 4. Карта родителя

1. Оставьте телефон ребёнка с включённым трекингом, телефон родителя — на главном экране карты.
2. Пройдите с ребёнком 100–200 м или включите передачу геопозиции.
3. Дождитесь появления/смещения маркера.
4. Нажмите на маркер ребёнка.
5. Откройте историю за сегодня, затем за вчера; проверьте полилинию и отмеченные остановки.

**Ожидаемо:** новая точка появляется на карте за 10–60 с (в покое — до 60 с); маркер соответствует реальному месту; имя ребёнка в списке; клик открывает историю; за сегодня/вчера есть маршрут, полилиния и остановки; пустой день показывает «За этот день нет данных».

## 5. Фон, блокировка, перезагрузка, Doze

1. Сверните приложение ребёнка и заблокируйте экран на 10–15 минут, двигаясь с телефоном.
2. Разблокируйте и проверьте карту родителя.
3. Перезагрузите телефон ребёнка, не открывая приложение.
4. Через 1–2 минуты после загрузки проверьте карту.
5. Оставьте телефон ребёнка неподвижно на час (экран выключен, приложение не открыто) и проверьте точки.

**Ожидаемо:** после сворачивания и блокировки точки продолжают приходить (интервал может вырасти до 60 с); после перезагрузки сервис поднимается сам, постоянное уведомление возвращается, новые точки появляются; в Doze точки не пропадают полностью — возможны более редкие обновления, периодический worker добирает пропущенное.

## 6. Настройки производителей (OEM)

Проверяйте на реальной прошивке, после каждого пункта — 30–60 минут в фоне.

### Xiaomi / Redmi (MIUI/HyperOS)

1. «Безопасность» → «Разрешения» → «Автозапуск» → включить Family Tracker.
2. «Батарея» → «Без ограничений» (или «Контроль активности» → «Без ограничений»).
3. Закрепите приложение в «Недавних», если прошивка это поддерживает.

**Ожидаемо:** точки идут в фоне, сервис не убит после блокировки экрана.

### Samsung (One UI)

1. «Батарея» → «Ограничения фоновой активности» → исключить Family Tracker из «Спящих приложений».
2. «Батарея» → «Без ограничений» для Family Tracker.

**Ожидаемо:** точки идут в фоне; после 1 часа без использования сервис жив.

### Huawei / Honor (EMUI/MagicOS)

1. «Диспетчер телефона» → «Запуск приложений» → Family Tracker: автозапуск, косвенный запуск, работа в фоне.
2. «Батарея» → «Запускать приложения в фоне» → разрешить.

**Ожидаемо:** сервис переживает блокировку экрана и не появляется в списке «закрытых» приложений.

### OPPO / Realme / OnePlus (ColorOS/OxygenOS)

1. «Настройки» → «Батарея» → «Запуск приложений» → разрешить автозапуск Family Tracker.
2. «Недавние» → меню приложения → «Заблокировать» (замок), чтобы очистка не убивала сервис.
3. При наличии — «Разрешить фоновую активность».

**Ожидаемо:** после очистки «Недавних» и блокировки экрана трекинг продолжается.

## 7. Офлайн и очередь

1. Включите на телефоне ребёнка авиарежим на 10–15 минут, двигаясь с телефоном.
2. Проверьте детский экран и карту родителя.
3. Выключите авиарежим и подождите 1–2 минуты.
4. Снова включите авиарежим.
5. Удерживайте SOS 2 секунды.
6. Выключите авиарежим.

**Ожидаемо:** в офлайне новые точки не появляются на карте родителя; после возврата сети накопленные точки уходят пакетом и карта догоняет. SOS в офлайне показывает «Пока не отправлено — отправим при появлении сети»; после возврата сети статус меняется на «Родитель получил сигнал», событие появляется у родителя.

## 8. SOS онлайн

1. На телефоне ребёнка нажмите и удерживайте SOS 2 секунды (виден прогресс).
2. Дождитесь «Родитель получил сигнал».
3. На телефоне родителя проверьте реакцию при открытом приложении, затем повторите при закрытом приложении и заблокированном экране.
4. Нажмите «Подтвердить получение».
5. Повторите подтверждение (из ленты/после перезапуска экрана).
6. В течение 30 секунд отправьте второй SOS.

**Ожидаемо:** SOS уходит с последними координатами; у родителя — полноэкранный сигнал или heads-up с высоким приоритетом, звук/вибрация, карта с точкой ребёнка; кнопка ack переводит событие в «Подтверждено» и убирает уведомление; повторный ack не создаёт ошибку и не меняет статус; второй SOS в течение 30 с не создаёт новое событие (cooldown сервера), в ленте остаётся одно.

## 9. Обрыв WebSocket и токен

1. Откройте карту родителя и убедитесь, что статус «Онлайн».
2. Отключите интернет на телефоне родителя на 30–60 секунд.
3. Верните интернет.
4. Повторите, перезапустив контейнер `ktor` на сервере (или отключив сеть сервера) на 30–60 секунд.
5. Проверьте статус и пропущенные точки.
6. Сбросьте семью на сервере (или отзовите токен) и откройте карту со старым токеном.

**Ожидаемо:** статус меняется на «Переподключение…», затем снова «Онлайн»; после восстановления карта добирает пропущенные точки через историю; при недействительном токене появляется «Нет доступа к серверу» (а не бесконечное переподключение без объяснения).

## 10. История SOS

1. Откройте «Тревоги» на телефоне родителя.
2. Проверьте список событий и имена детей.
3. Нажмите «Обновить».
4. Подтвердите неподтверждённое событие из ленты.

**Ожидаемо:** события отсортированы по времени, у каждого видны имя ребёнка, время, координаты/карта и статус «Подтверждено»/«Не подтверждено»; подтверждение сохраняется после обновления и перезапуска приложения; при отсутствии событий — «Тревог пока нет».

## 11. Батарея, трафик, БД и retention

1. Включите трекинг на 1–2 часа с обычной активностью.
2. Снимите расход: «Настройки → Батарея → Family Tracker» и «Настройки → Сеть → Использование данных».
3. На сервере посмотрите размер БД: `docker run --rm -v family-tracker_tracker_data:/data alpine ls -lh /data/tracker.db*`.
4. Проверьте, что в БД нет точек старше 30 суток (после суточного запуска retention), например через SQLite:
   `SELECT COUNT(*) FROM locations WHERE recorded_at < (strftime('%s','now') - 30*86400) * 1000;`
5. Убедитесь, что старые точки не возвращаются в истории и не растят БД бесконечно.

**Ожидаемо:** расход батареи и трафика остаётся разумным для фонового трекера (ориентир — единицы процентов за 1–2 часа, трафик — единицы МБ); БД растёт умеренно; записей старше 30 суток нет; старые точки исчезают.

## 12. Приватность и безопасность

1. Подключите телефон ребёнка к компьютеру и выполните `adb logcat`; пройдите по карте и отправьте точку.
2. На сервере просмотрите логи `docker compose logs ktor` после нескольких точек и SOS.
3. Раскодируйте QR (любым сканером, показывающим содержимое) и проверьте поля.
4. Попробуйте прочитать ntfy-тему без токена:
   `curl -i https://ntfy.example.com/family-<id>-sos/json`.
5. После сброса семьи проверьте старый родительский и детский токены:
   `curl -i -H 'Authorization: Bearer <старый_токен>' https://api.example.com/devices`.

**Ожидаемо:** в logcat нет координат, токенов и содержимого точек (только сообщения об ошибках без чувствительных данных); в логах сервера нет координат и токенов; QR содержит только `server` и одноразовый `code`, но не токен и не ntfy-токен; ntfy без авторизации отвечает `401/403`; после сброса семьи старые токены получают `401`, доступ к карте/истории невозможен.

## Известные ограничения

- **Остановки** определяются эвристикой по времени/скорости: короткие остановки могут сливаться, длинные — разбиваться; это ориентир, а не юридически точная хронология.
- **История** отдаёт не более **100 000 точек** за запрос; при слишком плотном диапазоне сервер возвращает `413 range too large`, приложение показывает ошибку. В UI истории доступно **7 дней назад**, сервер хранит **30 дней**.
- **FSI (full-screen intent)** на Android 14+ может быть запрещён пользователем/системой; тогда SOS остаётся heads-up-уведомлением. Приложение показывает карточку с настройкой; проверяйте оба режима.
- **OEM-прошивки** (Xiaomi, Samsung, Huawei, OPPO/Realme/OnePlus) могут убивать сервис несмотря на wizard; экраны настроек отличаются по версиям, проверка обязательна на конкретном телефоне.
- **Debug-подпись**: release APK подписан debug-ключом и предназначен только для sideload, не для Google Play. При смене ключа требуется переустановка (данные приложения будут потеряны).
- **Детский экран** не показывает отдельный статус соединения и время последней отправки: ориентируйтесь на карту родителя и постоянное уведомление трекинга, а офлайн-SOS явно пишет «Пока не отправлено».
- **Сброс/повторная привязка** выполняются очисткой данных приложения и/или сбросом семьи на сервере; отдельной кнопки «Отвязать» в приложении нет.
- HTTP-адрес сервера не поддерживается: приложение принимает только полный `https://` URL без пути.
