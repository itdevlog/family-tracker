# Семейный трекер местоположения — дизайн

Дата: 2026-10-20
Статус: черновик на согласование
Стек: Kotlin + Jetpack Compose (Android), Ktor (сервер), SQLite, ntfy, OpenStreetMap (osmdroid), Docker Compose

## 1. Назначение и границы

Одно Android-приложение с двумя ролями, выбираемыми при первом запуске (роль сохраняется до переустановки):

- **Родитель** видит живую карту с местоположением ребёнка, историю маршрутов, получает SOS-уведомления.
- **Ребёнок** отправляет координаты в фоне (~каждые 10–60 сек) и имеет кнопку SOS.

Инфраструктура — домашний Debian-сервер с доменом: Ktor-бэкенд + свой ntfy, всё за Caddy с HTTPS.

### В рамках v1
- Живая карта (обновление ~10–30 с при движении)
- История маршрутов за день (полилиния, остановки)
- SOS-кнопка с пушем родителю
- Wizard настройки детского телефона (устойчивость фону)

### Вне v1 (YAGNI)
- Геозоны и уведомления входа/выхода
- Экранное время, блокировка приложений, Device Owner
- Мультиродители, чаты, web-интерфейс
- iOS

## 2. Архитектура

```
[Детский Android] --HTTPS POST /locations (батчи)--> [Ktor] --> SQLite
                                     |
                                     +--> [ntfy] (только SOS)
[Родительский Android] --WS /live--> [Ktor]   (живые точки, когда приложение открыто)
                       --GET /locations--> [Ktor] (история, fallback живого канала)
                       --ntfy subscribe--> [ntfy] (SOS, когда приложение закрыто)
```

Один домен, Caddy маршрутизирует: `api.<домен>` → Ktor (:8080), `ntfy.<домен>` → ntfy (:8585).

## 3. Связывание родитель ↔ ребёнок

1. Родитель жмёт «Добавить ребёнка» → `POST /pair/code` → сервер выдаёт одноразовый 6-значный код (живёт 5 мин, привязан к семье родителя).
2. Родитель показывает **QR-код** (содержит URL сервера + код).
3. Ребёнок при первом запуске выбирает «Я ребёнок», сканирует QR или вводит код вручную → `POST /pair/child {code, name}`.

Шаг 0 — создание семьи: при первом запуске режима «Родитель» приложение регистрирует само себя: `POST /pair/parent {name}` → создаётся семья + родительское устройство, возвращается родительский токен. Строгое ограничение: **одна семья на инсталляцию сервера** (семейный сервер), поэтому «создать семью» имеет право лишь первый запрос, пока семья не создана.
4. Сервер создаёт детское устройство в семье и возвращает персональный токен (32 байта, base64url).
5. Токен хранится в EncryptedSharedPreferences, все дальнейшие запросы — `Authorization: Bearer`.

Структура: одна семья → N детей. Родитель знает свои устройства по своему токену.

## 4. Данные (SQLite)

```
families        id
devices         id, family_id, role(parent|child), name, token_hash, created_at
pair_codes      code, family_id, expires_at, used_by
locations       device_id, lat, lon, accuracy, speed, recorded_at
sos_events      id, child_id, lat, lon, created_at, acknowledged
```

Ретеншн: локации старше 30 дней удаляются раз в сутки фоновой задачей сервера.

## 5. API

| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| POST | `/pair/code` | родитель | создать код привязки |
| POST | `/pair/parent` | только до создания семьи | создать семью + устройство родителя |
| POST | `/pair/child` | любой (с валидным кодом) | создать детское устройство, вернуть токен |
| POST | `/locations` (батч до 100 точек) | ребёнок | отправить накопленные точки |
| POST | `/sos` | ребёнок | создать SOS → ntfy → родителю |
| GET | `/devices` | родитель | список своих детей + последние координаты |
| GET | `/locations?device&from&to` | родитель | история маршрута |
| GET | `/live?device=…` (WebSocket) | родитель | живой канал |

Все запросы кроме `/pair/child` — с Bearer-токеном. Ошибки — стандартные HTTP-коды + JSON `{error}`.

### Живой канал
- Открытое приложение родителя держит WS `/live`; каждая новая точка ребёнка пушится сервером всем родительским WS этой семьи.
- Обрыв WS → клиент добирает пропущенное через `GET /locations` (по времени последней полученной точки), потом WS восстанавливается с экспоненциальной задержкой.

### SOS
- Сервер по `/sos` пишет событие в БД и публикует HTTP-запросом в ntfy-тему `family-<id>-sos` (priority=high).
- WS тоже дублирует событие, если приложение родителя открыто.
- Родительское приложение подписано на ntfy-тему с auth-токеном (выдаётся при привязке вместе с токеном устройства).

## 6. Фоновый трекинг (детский режим)

- **Foreground service** с типом `location`, постоянное уведомление «Трекер работает». `startForeground()` обязателен; иначе система убивает процесс.
- **FusedLocationProviderClient**:
  - движение (скорость > 1 м/с или точки смещаются) → точка каждые **10 с**, `PRIORITY_HIGH_ACCURACY`
  - покой → точка каждые **60 с**, `PRIORITY_BALANCED_POWER_ACCURACY`
- Точки буферизуются в Room и отправляются батчами (до 100) через `POST /locations`; нет сети — копим, шлём позже.
- `START_STICKY` + `BroadcastReceiver` на `BOOT_COMPLETED` — сервис перезапускается.
- Дублирование потока точек: периодический `WorkManager`-джоб, если система усыпила сервис (Doze).

### Wizard устойчивости (детский телефон)

Экран-чеклист при первом запуске детского режима; каждый пункт проверяется автоматически:

1. Геолокация: «While using» → затем отдельный системный шаг «Allow all the time» (`ACCESS_BACKGROUND_LOCATION`).
2. Уведомления (`POST_NOTIFICATIONS`).
3. Исключение из оптимизации батареи (`PowerManager.isIgnoringBatteryOptimizations`; диалог `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`). APK ставится в обход Play Store, поэтому политика Play не ограничивает.
4. Настройки производителя (главный источник «убитых» трекеров):
   - Xiaomi/MIUI: Автозапуск + «Батарея → Без ограничений»
   - Samsung: исключить из спящих приложений, разрешить без оптимизации
   - Huawei/EMUI: «Запуск приложений» → автозапуск/косвенный запуск/фоновая активность
   - OPPO/Realme/OnePlus: автозапуск + замок в «недавних»
   - Stock Android: только пп. 1–3
   Каждый пункт открывает нужный системный экран (`startActivity`), статус ✓/✗ виден на чек-листе.

Device Owner / Device Admin **не используются** (не нужны для трекинга, требуют factory-reset). Возможная фаза 2.

Детский UI: статус соединения, «последняя отправка N мин назад», большая SOS-кнопка. Останов сервиса — через окно подтверждения.

## 7. SOS-сценарий

**Ребёнок:** красная кнопка по центру, активация **долгим нажатием 2 с** (прогресс-кольцо). `POST /sos` с последними координатами; нет сети — событие сохраняется и уходит при появлении сети. Экран «Родитель получил сигнал» / «пока не ушёл».

**Родитель:** ntfy-пуш с высоким приоритетом даже при закрытом приложении; при открытии — полноэкранный звонок + вибрацией, сразу карта с позицией ребёнка. В главном окне — лента SOS, кнопка «Отметить, что увидел» (`acknowledged`).

## 8. UI

**Родитель (Compose):**
- Карта (osmdroid, OpenStreetMap) с маркерами детей; лента снизу — выбор ребёнка.
- История: выбор дня, полилиния маршрута, точки остановок (данные из `GET /locations`).
- Лента SOS-событий.

**Ребёнок (Compose):**
- Большая SOS-кнопка, статус соединения, время последней отправки.

## 9. Сервер и деплой

Стек на Debian, Docker Compose:

- `caddy` (:443): HTTPS через Let's Encrypt; `api.<домен>` → ktor:8080, `ntfy.<домен>` → ntfy:8585
- `ktor` — бэкенд (jar в контейнере), SQLite-файл в volume
- `ntfy` — с auth-файлом; приватные темы
- Бэкап — копия файла SQLite + volume ntfy

## 10. Безопасность

- Всё через HTTPS; соединения без домена невозможны (baseUrl обязателен при первой настройке).
- Токены: 32 случайных байта, в БД — SHA-256 хеш.
- `/pair/child` брутфорс-защита: ограничение попыток с одного IP.
- Пары код → токен: код короткоживущий и одноразовый.
- ntfy-темы приватные (auth required).

## 11. Тестирование

- Сервер: unit-тесты Ktor (`testApplication`) — пары кодов, `/locations` батчи, `/sos` → проверка публикации, WS-пуши; интеграционный прогон в docker compose.
- Приложение: модульные тесты логики буферизации/интервалов; UI — вручную по сценариям (связывание, SOS, оффлайн→онлайн).
- Критические ручные сценарии: привязка QR → точка на карте ≤ 30 с; SOS при закрытом приложении родителя; телефон ребёнка в Doze → точки продолжают приходить; перезагрузка телефона → сервис сам поднялся; оффлайн-ребёнок → батч улетает после восстановления сети.

## 12. Этапы реализации (порядок)

1. Сервер: пары, `/locations`, WS — работает в compose за Caddy.
2. Приложение-каркас: выбор роли, экраны, настройки сети.
3. Детский режим: фоновый сервис + wizard устойчивости + батчи.
4. Родительский режим: карта, живой канал, история.
5. SOS end-to-end (кнопка → ntfy → пуш → карта).
6. Полевые проверки (Doze, перезагрузка, оффлайн, производители телефонов).
