# Family Tracker

Приложение для отслеживания местоположения ребёнка: Android-клиент с двумя ролями и собственный сервер на своём домене. Без Google-аккаунтов, Firebase и сторонних облаков — все данные хранятся на вашем сервере.

## Возможности

**Родитель**
- живая карта OpenStreetMap с обновлением по WebSocket;
- история маршрута за день с остановками;
- тревоги SOS: полноэкранный алерт, звук, вибрация, подтверждение получения;
- привязка ребёнка по QR-коду или шестизначному коду;
- push-уведомления через self-hosted [ntfy](https://ntfy.sh), в том числе при закрытом приложении.

**Ребёнок**
- фоновое отслеживание: 10 с при движении, 60 с в покое;
- офлайн-очередь: точки и SOS уходят при появлении сети;
- SOS по удержанию кнопки 2 секунды;
- мастер настройки разрешений и автозапуска для Xiaomi, Samsung, Huawei, OPPO/Realme;
- запуск после перезагрузки устройства;
- статус отправки: онлайн/офлайн, время последней успешной отправки, ошибки доступа.

## APK

Готовый release-APK: [последний релиз](https://github.com/itdevlog/family-tracker/releases/latest).

```bash
adb install -r app-release.apk
```

APK подписан debug-ключом и предназначен для sideload-установки, не для Google Play. При установке обновления поверх старой версии данные сохраняются; удаление приложения удаляет привязку и локальные настройки.

## Сборка приложения

Требования: JDK 17, Android SDK (platform 35, build-tools 35), `app/local.properties` с `sdk.dir=...`.

```bash
cd app
./gradlew test
./gradlew assembleDebug
./gradlew assembleRelease
```

APK появится в `app/app/build/outputs/apk/`.

## Сервер

Требования: Docker и Docker Compose на Debian-хосте, домен, открытые порты 80 и 443.

```bash
cd deploy
cp .env.example .env
chmod 600 .env
# заполните API_DOMAIN, NTFY_DOMAIN, ACME_EMAIL, NTFY_TOKEN
docker compose up -d --build
```

Caddy автоматически выпускает TLS-сертификаты. Наружу открыты только 80/443; Ktor и ntfy доступны лишь внутри Docker-сети.

Подробно: [deploy/README.md](deploy/README.md) — DNS, ntfy-пользователи и ACL, проверка токена, бэкап, восстановление, обновление, сброс семьи.

Если в сети уже есть Nginx Proxy Manager, Caddy можно не запускать — готовый override и настройка NPM описаны в разделе [«Вместо Caddy: Nginx Proxy Manager»](deploy/README.md#вместо-caddy-nginx-proxy-manager). Для Portainer есть отдельный `deploy/compose.portainer.yml` и раздел [«Portainer»](deploy/README.md#portainer).

Локальные тесты сервера:

```bash
cd server
./gradlew clean test
```

## Как это работает

1. Родитель вводит адрес сервера и создаёт семью. Сервер возвращает родительский токен и параметры ntfy.
2. Родитель показывает QR-код, ребёнок сканирует его или вводит шестизначный код вручную.
3. Ребёнок включает отслеживание и проходит мастер разрешений.
4. Точки копятся в Room и отправляются батчами; при обрыве сети остаются в очереди.
5. Родитель получает новые точки по WebSocket и догоняет пропущенное через историю.
6. SOS сохраняется на сервере, отправляется в WebSocket и в ntfy, после чего показывается полноэкранным алертом.

## Безопасность

- HTTPS обязателен; приложение не принимает `http://`.
- Токены устройств хранятся на сервере только в виде SHA-256.
- Одна установка сервера обслуживает одну семью.
- Первичная привязка открыта: сразу после деплоя создайте семью, иначе это сможет сделать любой, кто найдёт сервер.
- ntfy использует отдельного non-admin пользователя с ACL только на темы `family-*`.

## Ограничения

- Нет геозон, нескольких родителей, iOS и веб-версии.
- Фоновые ограничения Doze и прошивок производителей не обходятся: мастер помогает настроить устройство, но не гарантирует работу. Полевые сценарии — в [docs/checklist.md](docs/checklist.md).
- Release-подпись debug-ключом; смена ключа требует переустановки приложения.
- Полноэкранные SOS-алерты на Android 14+ зависят от разрешения системы; при отказе остаётся heads-up уведомление.
